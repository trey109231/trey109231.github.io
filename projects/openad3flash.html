AD3 programming / embedded bring-up tools

OpenAD3Flash: Microcontroller Programming & Flash Experiments

A collection of Python tools that use a Digilent Analog Discovery 3 as more than a scope: a target power supply, programmable digital interface, clock source, logic tool, and microcontroller/flash bring-up platform. The project grew from programming bare AVR and PIC devices into a broader set of experiments around low-level protocols, readout, glitching, and device recovery.

Role Solo tooling, protocol implementation, wiring, testing, and bench validation
Result Built reusable AD3-based tools for AVR ISP, PIC programming, I²C/SPI dumps, and read-only glitch experiments.
Repository Public repo available on GitHub.

Why this project matters

This project shows low-level embedded problem solving without relying on dedicated programmers or turnkey tools. It uses the AD3 as a flexible bench instrument and builds the missing protocol layers in Python: power sequencing, GPIO bit-banging, SPI/I²C transactions, programming-mode entry, flash verification, and waveform-assisted glitch experiments.

The value is not just programming old chips. The project demonstrates that I can read device programming specs, build practical tooling around real hardware constraints, protect the bench setup with careful wiring/safety assumptions, and debug systems at the protocol and signal level.

AVR ISP programmer

The AVR tool bit-bangs the standard AVR ISP interface using AD3 DigitalIO. It supports target power from the AD3, configurable pin mapping, signature read/autodetect, chip erase, Intel HEX parsing, flash programming, and verification. The implementation uses a device table so the protocol layer can support multiple classic AVR parts with different flash/page sizes.

  • Default AD3 ISP pins: RESET, SCK, MISO, MOSI, shared GND, and optional AD3 V+ target power.
  • Tested with ATmega168A and ATtiny84A-style workflows.
  • Device table entries include ATmega168/168P, ATmega328/328P, and ATtiny84/84A families.
  • Designed as a bench bring-up tool rather than a production programmer.

PIC16F84A high-voltage programmer + runtime experiments

The PIC16F84A tool controls VDD from the AD3, bit-bangs RB6/PGC and RB7/PGD, and drives an external VPP/MCLR switch for high-voltage programming. The tool can read device/config memory, dump original flash contents, bulk erase, parse and flash Intel HEX files, verify flash, and generate a runtime OSC1 clock from an AD3 digital output.

  • Implemented PIC14 word handling, Intel HEX parsing, dump/flash/verify flows, and test firmware generation.
  • Used an external 12 V VPP switch because the AD3 cannot directly drive PIC programming voltage.
  • Built and flashed small runtime firmware such as button/LED timing demos and shell-style experiments.
  • Saved original device contents before erasing old lab-bin parts.

PIC readout/glitch experiments

I also explored read-locked PIC behavior with read-only glitch experiments. The glitch tooling uses the AD3 waveform generator to power or perturb the target supply at specific moments in the programming/read sequence, while optionally capturing waveforms for later analysis. The goal was experimental characterization and learning, not destructive programming.

  • Generated event-aligned W1 glitches around read-command and shift-cycle timing.
  • Classified protected baseline reads, zero-read failure modes, and potentially interesting non-baseline responses.
  • Captured scope traces for selected attempts to correlate supply behavior with read results.
  • Kept the glitch workflow read-only: no erase/program commands in the glitch script.

I²C EEPROM and SPI flash dumping

The project also includes small memory-dumping tools. One script bit-bangs open-drain I²C to read 24C02-compatible EEPROMs, while another uses the AD3 Digital SPI engine to read 25Q-series SPI NOR flash such as the FM25Q16A. These tools are useful for firmware/asset extraction, board bring-up, and protocol practice.

  • 24C02 EEPROM dump tool uses open-drain-style AD3 GPIO with external pullups.
  • FM25Q16A SPI flash dumper reads JEDEC ID, status registers, and full 2 MiB flash contents.
  • SPI flash workflow includes conservative in-circuit read notes and read-only safety assumptions.
  • Follow-on analysis scripts decoded candidate image regions and embedded binary assets.

Distributed embedded computing experiment

Tiny AVR Mandelbrot Cluster

A small distributed Mandelbrot renderer built from five ATtiny84A microcontrollers, a Digilent Analog Discovery 3, and a Python host scheduler. Each worker computes one row of an ASCII Mandelbrot image when assigned a job, and the host dynamically schedules rows across the available chips.

Role Solo firmware, host software, wiring, programmer workflow, scheduler, and test/debug
Result Rendered an 80×40 ASCII Mandelbrot image across five ATtiny84A workers.
Repository Public repo available on GitHub.

Project overview

This project was built as a small but meaningful distributed-computing experiment. The Mandelbrot output is mostly an excuse to build the full stack: programming multiple tiny AVR chips, wiring a shared bus, writing worker firmware, handling shared MISO behavior, dynamically scheduling jobs from a Python host, and reconstructing the final output.

It is intentionally not fast. The interesting part is that the system behaves like a small compute cluster built from extremely limited microcontrollers.

Hardware architecture

The cluster uses five ATtiny84A microcontrollers as identical worker nodes. All workers share SCK, MOSI, and MISO lines, while each worker has its own chip-select line from the AD3. The AD3 also powers the targets from V+ during runtime.

  • 5× ATtiny84A workers on a shared SPI-style bus.
  • AD3 DIO0/DIO1/DIO2 used as shared SCK/MOSI/MISO.
  • Individual chip-select lines select worker 0–4.
  • Each worker tri-states MISO whenever it is not selected, allowing the shared MISO bus to work safely.
  • Workers were programmed using the separate AD3 AVR ISP tooling.

Worker firmware

Each ATtiny runs the same firmware. There is no per-chip address stored in firmware; the chip-select line acts as the address. The worker supports a tiny command protocol: ping, render row, and read row. The Mandelbrot calculation uses fixed-point math to avoid expensive floating-point and software division on the AVR.

  • 0xA0: ping; worker responds with 0x5A.
  • 0xB1 row: compute one Mandelbrot row and store it in an 80-byte row buffer.
  • 0xB2: read the stored ASCII row back to the host.
  • Fixed-point scale factor of 4096; inner-loop divisions are replaced with right shifts.
  • Character palette maps Mandelbrot escape iteration count to ASCII symbols.

Python host and scheduler

The Python host opens the AD3 through the WaveForms SDK, optionally enables target power, bit-bangs the shared SPI-style bus, pings all workers, assigns render jobs, polls for completion, reads rows back, and reconstructs the final ASCII image.

The scheduler is deliberately simple but effective: initially give one row to each worker, then whenever a worker finishes, read its result and assign the next available row. This matters because Mandelbrot rows do not all require the same amount of compute time.

Result

One 40×80 render completed in about 153 seconds using five workers and a conservative 1000 µs bit delay. The row distribution was uneven, which is expected and actually demonstrates why dynamic scheduling is useful: boundary-heavy rows take longer, so the fastest available worker receives the next row instead of statically assigning equal work.

What I would improve next

  • Add row checksums or CRCs and retry invalid rows.
  • Use a cleaner bus driver or AVR hardware USI/SPI approach.
  • Move the workers from breadboard wiring to a small backplane PCB.
  • Try an 8 MHz internal clock configuration.
  • Add timing/performance logging per row and per worker.
  • Render to an image file instead of ASCII only.

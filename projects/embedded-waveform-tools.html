Embedded waveform generation progression

AVR + STM32 Waveform Tools

A pair of embedded projects showing a progression from manual bare-metal waveform generation on an AVR with an external DAC to a more production-style STM32 workflow using timers, circular DMA, ADC capture, UART commands, and Python plotting.

Role Firmware, wiring, test tooling, and bench validation
Result Generated and captured waveforms using both low-level MCU control and hardware-timed DMA.
Status Public portfolio project; repo links and captures can be added once cleaned.

Why this project matters

This project pair shows the same core idea at two levels of abstraction. The AVR version is intentionally close to the metal: a timer interrupt advances a phase accumulator and writes samples to an external AD7528 DAC over a parallel GPIO bus. The STM32 version moves the real-time sample movement into hardware using timers and DMA, while the CPU handles commands and host communication.

Stage 1: AVR external-DAC waveform generator

The AVR version used an ATmega168A, an AD7528 external DAC, a 1602 LCD, joystick analog inputs, and an LM358 output buffer. The firmware drove the DAC data bus directly from PORTD, used Timer1 compare interrupts as the sample clock, and supported sine, square, ramp, and triangle outputs through a small LCD/joystick UI.

  • ATmega168A firmware written in manual AVR C with direct register access.
  • AD7528 8-bit external DAC controlled through an 8-bit parallel bus and GPIO control lines.
  • Timer1 ISR advanced a phase accumulator and wrote samples at a fixed sample rate.
  • LCD/joystick UI controlled waveform type, frequency, amplitude, and run/stop state.
  • Shared-port LCD/DAC conflicts were handled with careful interrupt masking around LCD writes.

Stage 2: STM32 ADC/DAC DMA loopback tool

The STM32 version used a NUCLEO-L432KC to generate DAC waveforms on PA4 and capture them back on PA0. TIM6 triggered DAC updates from a 256-sample waveform table through circular DMA, while TIM2 triggered ADC conversions into a circular DMA buffer. A UART command interface controlled waveform type, frequency, amplitude, offset, ADC sample rate, and binary capture transfer to a Python plotting script.

  • TIM6 → DAC trigger → DMA transfer from waveform table to DAC register.
  • TIM2 → ADC trigger → DMA transfer from ADC register into capture buffer.
  • UART command interface for waveform/capture control at 921600 baud.
  • Python host tool parsed binary ADC captures and plotted voltage vs. time.
  • Demonstrated a more serious embedded workflow using CubeMX/HAL, timers, DMA, and host tooling.

Technical comparison

AVR version CPU ISR writes each DAC sample directly. Excellent for learning the mechanics.
STM32 version Timers and DMA move samples in hardware. CPU handles configuration and communication.
Progression Manual sample loop → hardware-timed sample engine with capture and plotting.
